## gsc.js — Full Technical Details

**File:** `api/gsc.js`
**Last Updated:** May 30, 2026
**Purpose:** Easy SEO Report backend — GSC + GA4 data

### Authentication:
- OAuth 2.0 with offline access (refresh token)
- No user login required — uses pre-authorized refresh token for mae@aboutwallart.com
- GSC property: `sc-domain:aboutwallart.com` (domain property — NOT URL prefix)
- GA4 property ID: `359661193`

### Google Cloud Project:
- **Project:** Money Page Optimizer
- **Project ID:** `money-page-optimizer`
- **APIs Enabled:** Google Search Console API, Google Analytics Data API

### OAuth App:
- **App Name:** About Wall Art GSO Tools
- **Redirect URI:** `https://tools.aboutwallart.com/api/gsc`
- **Test User:** mae@aboutwallart.com
- **Scopes:** `webmasters.readonly` + `analytics.readonly` (BOTH required in same token)

### Supported Actions (GET ?action=):
- `overview` — total clicks, impressions, CTR, avg position
- `monthly` — monthly breakdown for historical view
- `queries` — all queries with impressions (rowLimit: 1000)
- `pages` — top pages by clicks (rowLimit: 500)
- `page-query` — page + query combined (rowLimit: 5000)
- `device` — device breakdown
- `blog-tracking` — performance of specific URLs (pass urls= param)
- `keyword-monthly` — monthly impressions+clicks for exact keyword (pass keyword= param) — used by Keyword Tracker growth chart
- `ga4-traffic-breakdown` — GA4 sessions by page path and month (rowLimit: 5000) — used by Suspicious Traffic stacked chart
- `ga4-suspicious` — GA4 sessions with bounce rate by month — used by Suspicious Traffic gauge
- `ga4-llm` — GA4 LLM/AI referral traffic (?days=30/90/180)
- `ga4-social` — GA4 social media traffic by platform + date (?days=365/730/1095/1460/1825)
- `ga4-social-pages` — GA4 social media traffic by platform + landing page (?days=365 etc)
- `reindex-batch` — Returns today's batch of 10 URLs for manual reindexing + formatted email HTML. Returns FLAT JSON (not nested under data). Fields: emailSubject, emailHtml, dayNumber, batchIndex, batchStart, totalBatches, batchUrls. Campaign start: 2026-06-07.

### CRITICAL: URL Format
GSC returns URLs WITHOUT www: `https://aboutwallart.com/`
Shopify builds URLs WITH www: `https://www.aboutwallart.com/`
Always normalise before matching:
```javascript
url.replace('https://www.aboutwallart.com', 'https://aboutwallart.com')
```

## blogs.js — Full Technical Details

**File:** `api/blogs.js`
**Last Updated:** May 30, 2026
**Purpose:** Blog Manager tool backend + all Easy SEO Report data storage actions

### GET Actions (?action=):

#### get-published-keywords
- Returns all Published Blog + To_Write_Blog keywords from registry CSV
- Returns: `{ success: true, publishedBlogs: [{keyword, url}] }`

#### get-registry
- Returns full keyword-locker-registry.csv as structured array
- Returns: `{ success: true, registry: [{keyword, url, locked, status, action}] }`
- Only rows with locked=LOCKED + status=DONE + action=TO_OPTIMIZE or OPTIMIZED count as truly locked

#### get-revenue-by-month
- Fetches last 13 months of revenue via Shopify REST Orders API
- Returns: `{ success: true, revenue: { YYYYMM: amount } }`
- NOTE: Currently returning 0 values — Shopify read_orders scope may need verifying
- Skips voided/refunded orders

#### get-susp-events
- Returns saved suspicious traffic chart events from data/suspicious-events.json
- Returns: `{ success: true, events: [{label, date}] }`

#### get-optimisations
- Returns keyword optimisation dates from data/keyword-optimisations.json
- Returns: `{ success: true, optimisations: { tabId: 'YYYY-MM-DD' } }`

#### get-tracked-keywords
- Returns tracked keyword list from data/tracked-keywords.json
- Returns: `{ success: true, keywords: ['kw1', 'kw2', ...] }`

#### get-keyword-tabs
- Returns keyword tracker tabs from data/keyword-tracker.json
- Returns: `{ success: true, tabs: [{id, label, keyword}] }`

#### GET (no action) — Blog ideas pipeline (for Blog Manager tool)

### POST Actions (req.body.action):

#### lock-keyword
- Saves keyword+URL to keyword-locker-registry.csv on GitHub
- Format: LOCKED, DONE, TO_OPTIMIZE, User Resolved
- Body: `{ action: 'lock-keyword', keyword, url }`

#### save-susp-events
- Saves suspicious traffic chart events to data/suspicious-events.json
- Body: `{ action: 'save-susp-events', events: [{label, date}] }`

#### save-optimisations
- Saves keyword optimisation dates to data/keyword-optimisations.json
- Body: `{ action: 'save-optimisations', optimisations: { tabId: 'YYYY-MM-DD' } }`

#### save-tracked-keywords
- Saves tracked keywords list to data/tracked-keywords.json
- Body: `{ action: 'save-tracked-keywords', keywords: [...] }`

#### save-keyword-tabs
- Saves keyword tracker tabs to data/keyword-tracker.json
- Body: `{ action: 'save-keyword-tabs', tabs: [{id, label, keyword}] }`

#### get-autolink-rules
- Returns all 368 auto-link rules from data/autolink-rules.json
- Returns: `{ success: true, rules: [{id, keyword, url, linksAdded}] }`

#### save-autolink-rules
- Saves full rules array to data/autolink-rules.json
- Body: `{ action: 'save-autolink-rules', rules: [{id, keyword, url, linksAdded}] }`

#### get-metafield-links
- Returns tracked product→article metafield links from data/metafield-product-links.json
- Returns: `{ success: true, links: [{productId, articleId}] }`
- Only tracks products added via this tool — does NOT scan Shopify metafields

#### save-metafield-links
- Saves full metafield links array to data/metafield-product-links.json
- Body: `{ action: 'save-metafield-links', links: [{productId, articleId}] }`

#### get-social-revenue (GET)
- Fetches Shopify orders and groups revenue by social referring site
- Query param: `?days=365` (default 90, supports up to 1825 for 5 years)
- Filters orders where `referring_site` contains a known social domain (facebook, instagram, pinterest, tiktok, youtube, twitter, t.co, x.com, linkedin)
- Returns: `{ success: true, byPlatform: { 'Facebook': 120.50, ... }, byPage: { '/blogs/...': { total, orders, topPlatform } } }`
- Skips voided/refunded orders
- Requires `read_orders` scope on SHOPIFY_ACCESS_TOKEN

#### POST (no action) — Mark blog as To Write (Blog Manager)
#### PATCH — Mark as Keyword Change (Blog Manager)
#### DELETE — Undo (Blog Manager)

- Non-blocking

# LINK WHISPERER TOOL — COMPLETE DOCUMENTATION

**File:** `link-whisperer.html`
**Current Version:** v16.61 (June 6, 2026)
**URL:** https://tools.aboutwallart.com/link-whisperer.html
**Purpose:** Internal linking manager — replicates Link Whisper (WordPress plugin) for Shopify. Manages inbound and outbound internal links across all site content. Also detects keyword cannibalization and auto-applies link rules to new content via Shopify webhooks.

---

## API Backend

All Shopify calls go through `api/shopify-files.js`. No new API files were created (Vercel function count remains 11/12).

### Action branches in `api/shopify-files.js`:

#### `action=link-whisperer` (REST proxy — GET and PUT)
- Reads `endpoint` and `method` query params
- Forwards to: `https://${SHOPIFY_STORE_DOMAIN}/admin/api/2025-01/${endpoint}`
- Header: `X-Shopify-Access-Token`
- Passes through Shopify `Link` header for pagination
- Used for: reading products, pages, articles, collections, writing body HTML changes

#### `action=link-manager` (REST proxy — identical logic, separate action name)
- Same as link-whisperer but triggered by `action=link-manager`
- Kept for backwards compatibility

#### `action=autolink-webhook` (POST — called by Shopify webhooks)
- Fires when a new product or collection is created in Shopify
- Verifies `x-shopify-domain` header matches store domain
- Loads rules from `data/autolink-rules.json` on GitHub
- Loads settings from `data/lw-settings.json` on GitHub
- Applies keyword→URL rules to the new item's body_html
- Saves updated body_html back to Shopify
- Updates `linksAdded` counts in `data/autolink-rules.json`
- Topics handled: `products/create`, `collections/create`
- NOTE: Shopify does NOT support webhook topics for blog article creation in either REST or GraphQL API — articles cannot be auto-linked

#### `action=register-autolink-webhooks` (POST — called from Settings tab button)
- Deletes existing webhooks with our address
- Registers `products/create` and `collections/create` webhooks (REST API)
- Webhook address: `https://tools.aboutwallart.com/api/shopify-files?action=autolink-webhook`
- 300ms delays between calls to avoid Shopify rate limiting

#### `action=create-redirects` (POST — TO BE BUILT for Technical Health tab)
- Body: `{ redirects: [{from, to}] }`

## Broken Links Report — Architecture (v16.54)

### What works:
- Groups broken URLs — one row per unique broken URL
- Large groups (>20 pages) automatically split into rows of 20 with batch label "(1/13)"
- Tab badge shows count of unique broken URLs
- Search box finds products, collections, blogs and pages by keyword
- Full URL paste supported (shows "Use this URL directly →" option)
- Sort by any column including Affects (number of pages) ↕
- Email addresses filtered out from broken links list
- Homepage (`https://aboutwallart.com`) and blog index pages whitelisted — never flagged as broken
- All URLs with `?` query params (variant, tracking etc) auto-fixed on sync and cache load — query string stripped, clean URL saved to Shopify. If clean URL is also broken it returns as plain 404
- Archived products detected — orange "Archived product" badge, filter dropdown shows count, SELECT ALL ARCHIVED button
- DELETE SELECTED calls Shopify API to remove `<a>` tags from all affected pages (not just UI dismiss)
- ACCEPT SELECTED SUGGESTIONS button — tick multiple rows, accept all their auto-suggestions at once
- Auto-suggestions filtered by content type (blogs suggest blogs, products suggest products etc)
- Search box always visible below suggestion — no need to click Change
- Save/Remove work correctly and persist after Refresh Data

### URL normalisation — CRITICAL
`normaliseHref(href)` shared helper used by both replace and remove functions:
- Converts relative `/path` to `https://aboutwallart.com/path`
- Strips `www.` from domain
- Strips trailing slash, lowercases
**This fixed the save-not-persisting bug** — hrefs stored with `www.` never matched before v16.43.

### Key data structures:
- `AppState.brokenLinks` — `{sourceId, brokenUrl, anchorText, type, status, reason, discovered, suggested, suggestedChecked}`
  - `reason`: null = normal 404, `'archived-product'` = archived product
  - `suggested`: `{ item, confidence, label, alternatives }` populated by `computeBrokenLinkSuggestions()`
- `AppState.variantFixQueue` — `[{sourceId, brokenUrl, cleanUrl}]` — URLs with `?` queued for auto-fix
- `BlState.pendingFixes` — Map of `groupKey → {groupKey, brokenUrl, newUrl, newTitle, sourceIds[], idx}`
- `BlState.selected` — Set of selected groupKeys
- `BlState.groupRegistry` — Map of `groupKey → group object` (rebuilt on each render)
- Group key = `brokenUrl` for groups ≤ 20, `brokenUrl + '::' + chunkIndex` for larger groups

### URL replacement functions:
- `normaliseHref(href)` — shared normalisation helper (strips www, converts relative to absolute, lowercase)
- `replaceUrlInHtml(html, brokenUrl, newUrl)` — uses DOMParser + normaliseHref, returns original html if nothing changed
- `removeLinkFromHtml(html, brokenUrl)` — uses DOMParser + normaliseHref, unwraps `<a>` tags, returns original html if nothing changed

### Save flow:
- `saveAllPendingFixes()` — uses stored `sourceIds` directly, batches of 5, 300ms pause between rounds
- After save: removes saved entries from AppState.brokenLinks directly, badge updated manually

### Auto-fix flow:
- `processVariantAutoFixes()` — runs on both fresh sync AND cache load
- Strips `?` from any URL with query params, saves clean URL to Shopify
- Shows toast: "Auto-fixed variant URLs on X pages"

### Known issue — suggestion quality:
Auto-suggestions use `findBestUrlMatch()` which scores by handle similarity and keyword overlap. Common words like "interior", "design", "home" cause weak false matches. User works manually with the search box. Future session should raise the confidence threshold or only show near-exact matches.

# KEYWORD LOCKER TOOL — COMPLETE DOCUMENTATION

**File:** `keyword-locker.html`
**Current Version:** v6.0 (June 6, 2026)
**URL:** https://tools.aboutwallart.com/keyword-locker.html
**Purpose:** Detects keyword cannibalization conflicts using live GSC data and allows locking each keyword to its best URL. Intent-aware — only flags pages competing for the same keyword with the same intent as conflicts.

---

## How It Works

1. Loads live GSC page-query data (last 90 days, up to 25,000 rows) via `/api/gsc?action=page-query`
2. Loads keyword registry from `/api/blogs?action=get-registry`
3. Detects conflicts: same keyword appearing on 2+ pages with the same intent
4. Scores each competing URL and pre-selects the best winner
5. User resolves conflicts — winner locked, losers saved for internal linking

---

## Conflict Detection Logic

### URL Normalisation (applied before any grouping):
- Strip `?query_params`
- Strip `#fragments`
- Strip trailing slash
- Replace `https://www.aboutwallart.com` with `https://aboutwallart.com`

### URL Filters (excluded from conflicts):
- Foreign language: `/es/`, `/fr/`, `/de/`, `/it/`, `/pt/`, `/nl/`, `/ru/`, `/ja/`, `/zh/`, `/ko/`, `/ar/`
- CDN: `/cdn/`
- Junk pages: `write-for-us`, `contact`, `about-us`, `privacy`, `terms`, `wishlist`, `loyalty`, `confirm-your-email`

### Intent Detection (from URL pattern):
- `/blogs/` → INFORMATIONAL
- `/collections/` → COMMERCIAL
- `/products/` → COMMERCIAL
- `/pages/` → NAVIGATIONAL
- Homepage → NAVIGATIONAL

### Conflict Rules:
- A conflict = same keyword on 2+ pages WITH THE SAME INTENT
- Different intent (blog + collection for same keyword) = NOT a conflict
- Same keyword can appear in multiple conflicts if different intents

### Registry Filtering:
- Pre-Optimized Page entries → keyword+intent fully handled, URL locked (cannot be winner)
- User Resolved TO_OPTIMIZE entries → keyword+intent handled, URL locked
- SAVED_FOR_FUTURE or DELETED entries → keyword fully skipped
- Published Blog entries → NOT pre-filtered (appear freely in conflicts)

### Winner Scoring:
- Page type priority: Collection (400) > Blog (300) > Product (200) > Page (100)
- URL slug keyword match: up to 300 points
- Position bonus: (20 - position) × 5, max when position = 1
- Impressions: min(impressions/10, 50)
- Clicks: min(clicks×2, 50)

### Conflict Sorting:
- Sorted by winner score descending — strongest pre-selected winner shown first
- Ensures best pages get locked before they're taken by other conflicts

---

## Special Cases

### Only 1 unlocked URL remains in a conflict:
- Green notice shown: "All other competing pages are already locked. Click Confirm to lock it."
- Confirm & Lock button — saves as User Resolved (not automatic)

### All URLs locked in a conflict:
- Yellow notice shown: "All competing pages are already locked to other keywords."
- Remove button — saves as DELETED, removes from active conflicts

### Real-time locking:
- When a URL is locked as winner, `lockedUrlsRuntime` Set is updated immediately
- All other conflict cards refresh — newly locked URLs show LOCKED badge and become unselectable
- No page reload needed

## Registry Format

**File:** `data/keyword-locker-registry.csv`
**Columns:** Keyword, Page URL, LOCKED, Status, Action, WinnerURL, Clicks, Impressions, Position, Source, INTENT

| Row Type | LOCKED | Status | Action | Source | INTENT |
|----------|--------|--------|--------|--------|--------|
| Winner | LOCKED | DONE | TO_OPTIMIZE | User Resolved | COMMERCIAL/INFORMATIONAL/NAVIGATIONAL |
| Loser | (blank) | DONE | INTERNAL_LINK | Auto Detected | same as winner |
| Saved for Later | LOCKED | DONE | SAVED_FOR_FUTURE | User Action | intent |
| Deleted | LOCKED | DONE | DELETED | User Action | intent |
| Pre-Optimized Page | LOCKED | DONE | (blank) | Pre-Optimized Page | COMMERCIAL/NAVIGATIONAL |
| Published Blog | (blank) | DONE | (blank) | Published Blog | INFORMATIONAL |

**Important:** All CSV fields with commas are wrapped in double quotes when saved.

## API Calls Made by keyword-locker.html:
- `GET /api/gsc?action=page-query&startDate=YYYY-MM-DD&endDate=YYYY-MM-DD` — 90 days, 25,000 rows
- `GET /api/blogs?action=get-registry` — full registry
- `POST /api/blogs` action=`lock-keyword` — save winner + losers
- `POST /api/blogs` action=`save-for-later` — save for later
- `POST /api/blogs` action=`delete-keyword` — delete keyword
- `POST /api/blogs` action=`remove-from-registry` — undo (removes all rows for keyword)

---

## blogs.js Actions Added for Keyword Locker (v1.3):

### lock-keyword (POST)
- Body: `{ action, keyword, url, intent, losers: [{url, clicks, impressions, position}] }`
- Saves winner row: `keyword,url,LOCKED,DONE,TO_OPTIMIZE,N/A,N/A,N/A,N/A,User Resolved,INTENT`
- Saves loser rows: `keyword,url,,DONE,INTERNAL_LINK,winnerUrl,clicks,impressions,position,Auto Detected,INTENT`

### save-for-later (POST)
- Body: `{ action, keyword, intent }`
- Saves: `keyword,N/A,LOCKED,DONE,SAVED_FOR_FUTURE,N/A,N/A,N/A,N/A,User Action,INTENT`

### delete-keyword (POST)
- Body: `{ action, keyword, intent }`
- Saves: `keyword,N/A,LOCKED,DONE,DELETED,N/A,N/A,N/A,N/A,User Action,INTENT`

### remove-from-registry (POST)
- Body: `{ action, keyword }`
- Removes ALL rows for that keyword from registry (winner + losers)

### get-registry (GET) — updated to return:
- keyword, url, locked, status, action, winnerUrl (col5), source (col9), intent (col10)

## Stat Cards (click to view):
- **Active Conflicts** — number of conflict groups remaining
- **Resolved** — User Resolved TO_OPTIMIZE entries only
- **Saved for Later** — SAVED_FOR_FUTURE entries (content opportunities)
- **Deleted** — DELETED entries (noise keywords)
- **Pre-locked** — Pre-Optimized Page entries (6 pages, grows as pages optimised)
- **Internal Links to Add** — INTERNAL_LINK entries (loser pages needing a link to winner)
