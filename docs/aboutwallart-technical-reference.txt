## blogs.js — Full Technical Details

**File:** `api/blogs.js`
**Last Updated:** May 27, 2026
**Purpose:** Blog Manager tool backend — handles all blog data operations AND Google Sheets integration

### Supported HTTP Methods:

#### GET — Read published blogs from registry
- Reads `data/keyword-locker-registry.csv` from local filesystem
- Filters rows where `Source` column (index 9) = `Published Blog`
- Returns: `{ blogs: [{title, keyword, status, url, date}] }`

#### POST — Mark blog as "To Write"
- Reads `keyword`, `url`, `title`, `perspective` from request body
- Does 3 things in sequence:
  1. Appends row to `data/keyword-locker-registry.csv` on GitHub (via GitHub API)
  2. Updates `data/blog_ideas.csv` on GitHub — sets STATUS column to `TO_WRITE`
  3. Calls Google Sheets webhook (non-blocking — won't fail if Sheets fails)
- Returns: `{ success: true, keyword, url, sheetsResult }`

#### PATCH — Mark as Keyword Change
- Updates `data/blog_ideas.csv` — sets STATUS to `KEYWORD_CHANGE`

#### DELETE — Undo
- Removes entry from `data/keyword-locker-registry.csv`
- Clears STATUS in `data/blog_ideas.csv`

### Google Sheets Integration (added May 27, 2026):
- Uses Google Apps Script Web App as webhook (no OAuth/credentials needed)
- Apps Script runs as the Google account owner, has automatic Sheet access
- Webhook URL stored in Vercel env var: `SHEETS_WEBHOOK_URL`
- If `SHEETS_WEBHOOK_URL` not set, Sheets append is silently skipped
- Non-blocking: if Sheets fails, the whole request still succeeds
- Column mapping when row is appended:
  - Column A (index 0) = `BLOG MANAGER TOOL` (fixed text)
  - Column B (index 1) = Perspective
  - Column C (index 2) = Main Keyword
  - Column F (index 5) = Blog Post Title
  - Column AS (index 44) = `READY TO GENERATE BLOG` (fixed text)
  - All other columns = empty

### Google Apps Script (Sheets Webhook):
- **Script name:** Sheets Webhook
- **Google Sheet ID:** `1W9AYH2Zcw-v2U6S47a3w5bs5rEBf6K30adDgNkaZ38k`
- **Tab:** Sheet1
- **Deployed as:** Web App, Execute as: Me, Who has access: Anyone
- **Script code:**
```javascript
function doPost(e) {
  const sheet = SpreadsheetApp.openById('1W9AYH2Zcw-v2U6S47a3w5bs5rEBf6K30adDgNkaZ38k').getSheetByName('Sheet1');
  const data = JSON.parse(e.postData.contents);
```

## `/data/` Folder

### Active Data Files:

#### `keyword-locker-registry.csv`
- Central database of all locked keywords
- Prevents keyword cannibalization
- All tools read from and write to this file
- Column structure: `Keyword, Page URL, LOCKED, Status, Action, Clicks, Position, Match Score, AI Score, Source`
- Source values: `Published Blog`, `To_Write_Blog`, `Collection Page`, etc.
- 378+ published blogs as of May 27, 2026

#### `blog_ideas.csv` (NEW - May 27, 2026)
- Blog idea pipeline — list of candidate blog posts with conflict detection
- Column structure: `Keyword, Blog Post Title, Perspective, CANNIBALIZATION, CONFLICTING KEYWORD, CONFLICTING BLOG URL, STATUS`
- CANNIBALIZATION values: `NO CONFLICT`, `CAUTION`, `DANGER`
- STATUS values: `TO_WRITE`, `TO_WRITE` (from registry), `KEYWORD_CHANGE`, empty
- Read by `blogs.js` GET handler
- Updated by `blogs.js` POST/PATCH/DELETE handlers
- Currently contains 50 processed ideas



### Blog Ideas Conflict Detection Algorithm:
```python
# Jaccard similarity on core words
stop_words = {'how','to','a','an','the','your','my','for','in','with',...}
def extract_core(keyword): return [w for w in keyword.lower().split() if w not in stop_words and len(w) > 2]
def jaccard(k1, k2):
    w1, w2 = set(extract_core(k1)), set(extract_core(k2))
    return len(w1 & w2) / len(w1 | w2)

# Thresholds:
# >= 0.6 → DANGER
# >= 0.4 → CAUTION
# < 0.4  → NO CONFLICT
```

### STATUS sync rule:
When processing new blog ideas, check `keyword-locker-registry.csv` for rows where Source = `To_Write_Blog`. If keyword matches, set STATUS = `TO_WRITE` in blog_ideas.csv.

# CORS CONFIGURATION

All API files MUST include CORS headers at the top of the handler. See `blogs.js` section above for the standard headers block. This is required to prevent browser CORS errors when the frontend calls the API.

**vercel.json** also sets CORS headers at infrastructure level:
```json
{
  "redirects": [{
    "source": "/:path*",
    "has": [{ "type": "host", "value": "seo-tools-lake.vercel.app" }],
    "destination": "https://tools.aboutwallart.com/:path*",
    "permanent": true
  }],
  "headers": [{
    "source": "/api/(.*)",
    "headers": [
      { "key": "Access-Control-Allow-Origin", "value": "*" },
      { "key": "Access-Control-Allow-Methods", "value": "GET, POST, PUT, DELETE, OPTIONS" },
      { "key": "Access-Control-Allow-Headers", "value": "Content-Type, Authorization" }
    ]
  }]
}
```

# BLOG IDEAS PROCESSING WORKFLOW

## How to add more ideas to blog_ideas.csv:

1. User provides a source file (xlsx or csv) with new blog ideas
2. Download current `blog_ideas.csv` from GitHub — note which keywords are already in it
3. Filter out rows already in blog_ideas.csv
4. Take next N rows (recommend batches of 10-50)
5. Run Jaccard conflict detection against `keyword-locker-registry.csv`
6. For each new row: check if keyword exists in registry with Source=`To_Write_Blog` → if yes, set STATUS=`TO_WRITE`
7. Append new rows to existing blog_ideas.csv (DO NOT replace — preserves previous work)
8. Upload updated blog_ideas.csv to GitHub at `data/blog_ideas.csv`

# TROUBLESHOOTING

## CORS Errors
- Verify CORS headers are in the API file
- Verify `vercel.json` has correct CORS config
- Redeploy after changes
- Hard refresh browser

## Claude API fails
- Check model name: must be exactly `claude-sonnet-4-6`
- Check `ANTHROPIC_API_KEY` is set in Vercel env vars
- Check Vercel logs for specific error

## Google Sheets not receiving data
- Check `SHEETS_WEBHOOK_URL` is set in Vercel env vars
- Verify Apps Script is deployed as Web App with "Anyone" access
- Check Vercel logs — `sheetsResult` in API response shows success/error
- Non-fatal: even if Sheets fails, the rest of the save still works

## blog_ideas.csv not loading in tool
- Check file exists at `data/blog_ideas.csv` in GitHub
- Check `blogs.js` GET handler — reads from local filesystem, file must be in `data/` folder at repo root
- Verify Vercel has redeployed after CSV update

## Vercel function limit
- Already at 12/12 functions
- Cannot add new `.js` files to `/api/` folder
- Add new functionality as new actions inside existing API files
